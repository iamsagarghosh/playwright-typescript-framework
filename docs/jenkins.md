# Jenkins setup

This guide covers the repository's initial Jenkins integration for a local Windows installation.
The pipeline definition lives in `.jenkins/Jenkinsfile`, separate from the GitHub Actions and
Azure Pipelines definitions.

## Scope

- Runs on the Jenkins Built-In Node using `agent any`.
- Targets only the local Leap & Leash demo (`TEST_ENV=local`); it does not accept an arbitrary URL or
  credentials.
- Lets a manual run select a suite, browser project(s), and worker count.
- Runs lint, formatting, TypeScript checks, and the selected Playwright suite.
- Publishes JUnit results and archives the Playwright HTML report and available test diagnostics.
- Does not configure a schedule, webhook, or automatic GitHub trigger.

The Built-In Node is suitable for this personal local validation setup. Jenkins discourages using
the controller's Built-In Node for production builds because builds share resources with the
controller. Use a separate Windows agent if this setup becomes shared or production-facing.

## Prerequisites

Install the following on the Windows machine running Jenkins:

- A Jenkins-supported 64-bit Java runtime
- Node.js 24 and npm
- Git for Windows
- Microsoft Edge if you select the Edge browser project

The Jenkins process must be able to find `node`, `npm`, and `git` on `PATH`. If Jenkins runs as a
Windows service, its environment may differ from the interactive PowerShell session. Restart the
Jenkins service after changing its system `PATH`.

## Create a manual Pipeline job

1. In Jenkins, select **New Item** and create a **Pipeline** job, for example
   `Playwright UI Automation`.
2. In the job configuration, select **Pipeline script from SCM**.
3. Select **Git** and enter the public GitHub repository URL:
   `https://github.com/iamsagarghosh/playwright-typescript-framework.git`
4. Set the branch specifier to `*/main` and the script path to `.jenkins/Jenkinsfile`.
5. Save the job, then select **Build with Parameters**.

The first run may need to be started once before Jenkins displays the parameters defined by the
Jenkinsfile. Choose the suite, browser project(s), and worker count, then start a build.

## Review results

The **Test Result** link shows the published JUnit results. Open the build's **Artifacts** section
and download `playwright-report/index.html` to view the interactive Playwright report. The
`test-results` folder contains JUnit XML and any failure screenshots, videos, traces, or test-scoped
execution logs generated by the run. Successful tests do not retain failure diagnostics.

## Later: branch and pull request validation

After the manual pipeline works, create a **Multibranch Pipeline** job using the GitHub repository
and set its script path to `.jenkins/Jenkinsfile`. Configure branch and pull request discovery, then
verify a pull request build before making it a required check. A Jenkins controller reachable only
on `localhost` cannot receive GitHub webhooks; use a periodic repository scan until a secured,
reachable webhook endpoint is deliberately configured.

Do not put a GitHub token, application credentials, or other secrets in the Jenkinsfile or
repository. A public repository can be checked out without a read token. If credentials are needed
later, store them in Jenkins Credentials and scope them to the relevant job.
