# Playwright TypeScript Automation Framework

An application-independent UI automation framework built with Playwright Test and strict TypeScript.
Initial workflows use Leap & Leash, a retail demo app. Amazon.in remains a future target, subject to
appropriate authorization and an approved test environment.

## Prerequisites

- Node.js LTS and npm
- Git
- Visual Studio Code (recommended)

## Setup

```powershell
npm install
Copy-Item .env.example .env
npm run browsers:install
```

For local execution, the environment defaults to the Leap & Leash demo. QA, staging, and UAT require
an explicit `BASE_URL`. Do not place production credentials or personal account information in
`.env`. The Playwright browser binaries are stored in the ignored `.playwright-browsers` folder by
the project CLI wrapper, so install and test commands use the same browser location on Windows and
CI agents.

## Environment and test data

`TEST_ENV` accepts `local`, `qa`, `staging`, or `uat`. Local defaults to the Leap & Leash demo URL;
the other environments require an explicit authorized `BASE_URL`. `getTestCredentials()` reads
`TEST_USERNAME` and `TEST_PASSWORD` only when an authentication workflow requests them, and never
logs those values.

Each environment loads its validated dataset from `test-data/<environment>.json`; the local demo
dataset is `test-data/local.json`. A missing or malformed dataset fails clearly instead of reusing
another environment’s data. `createTestCustomerData()` generates synthetic names and unique
addresses under the reserved `example.test` domain for guest checkout tests.

Current cart and checkout tests use the guest flow only. Checkout uses synthetic customer data and
the demo card option; the demo FAQ states that payment is frontend-only and contacts no external
payment service. No sign-in or personal account data is used.

## Quality commands

```powershell
npm run lint
npm run format:check
npm run typecheck
```

Run all configured browser projects with `npm test`. To select one browser, use `npm run
test:chromium` or `npm run test:edge`. The Edge project uses the installed Microsoft Edge browser.
Tests can also be filtered by suite:

```powershell
npm run test:smoke
npm run test:sanity
npm run test:regression
npm run test:e2e
```

Smoke and sanity intentionally overlap for the search and navigation checks. Override the local
worker default for parallel validation with `npm run test:chromium -- --workers=2`; run both browser
projects with two workers total using `npm test -- --workers=2`. Each test gets a fresh Playwright
browser context through the built-in `page` fixture, and environment JSON is loaded as read-only
data. Dynamic checkout customers are generated per test.

Screenshots, videos, and traces are configured for failing tests under `test-results/artifacts`;
successful runs do not retain these failure diagnostics. HTML and JUnit reports are generated by
each run under `playwright-report` and `test-results/junit.xml`.

## Reviewing reports and failure diagnostics

Open the latest interactive HTML report with:

```powershell
node scripts/playwright-cli.cjs show-report
```

The JUnit XML is intended for CI test result publishers and can also be opened as text or parsed
with an XML tool. When a test fails, Playwright prints the attachment paths in the test output.
Open a retained trace using the printed path:

```powershell
node scripts/playwright-cli.cjs show-trace test-results/artifacts/<failed-test-folder>/trace.zip
```

The trace viewer includes the action timeline, DOM snapshots, network activity, and console output.
The same failed-test folder contains the screenshot and retained video when available. Report and
artifact directories are ignored by Git; publish them from CI as test results and pipeline artifacts.

## Azure Pipelines definitions

The repository contains pipeline YAML prepared for later Azure DevOps registration:

- `azure-pipelines-pr.yml`: GitHub pull request validation on `main`, with lint, formatting,
  TypeScript checks, Chromium smoke tests, JUnit results, and Playwright artifacts.
- `azure-pipelines-regression.yml`: daily regression and E2E runs in Chromium and Edge at 20:00 UTC
  (01:30 India Standard Time), with JUnit results and Playwright artifacts.
- `azure-pipelines-manual.yml`: manually selected environment, browser, and suite.

These files do not create or run Azure DevOps pipelines by themselves. The GitHub repository must be
connected when the pipelines are registered. For QA, staging, or UAT manual runs, add the matching
`playwright-qa`, `playwright-staging`, or `playwright-uat` variable group with an authorized
`BASE_URL`, and add the corresponding `test-data/<environment>.json` file. Local demo execution
needs no credentials. No production or authentication workflow is configured.

## GitHub Actions

GitHub Actions workflows are available under `.github/workflows`:

- `playwright-pr.yml` runs lint, formatting, TypeScript checks, and Chromium smoke tests on pushes to `main` and pull requests targeting `main`.
- `playwright-regression.yml` runs the regression and E2E suites daily in Chromium and Edge. It can also be started manually with a selected suite and browser project.

Both workflows use the local Leap & Leash demo configuration, require no credentials, and upload the HTML report, JUnit results, and available failure diagnostics as workflow artifacts. These workflows are separate from the Azure Pipelines definitions; adding them to Git does not run or configure Azure DevOps.
